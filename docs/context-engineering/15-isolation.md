# 15｜Isolation：让每个问题只带自己的行李

一个复杂任务经常同时包含多个子问题。

最省事的做法，是让所有步骤共享同一份大 Context。

短期方便，长期却会出现一个熟悉的现象：每个人都带着整间仓库去开会。

财务分析里混着用户评论，产品判断里塞着完整财报，某个子任务刚形成的猜测又悄悄影响了另一个子任务。

Isolation 处理的就是这种问题。

## 按工作单元划边界

假设要研究一家公司的投资价值，可以拆成：

- 财务；
- 产品；
- 市场；
- 风险。

这些工作会共享公司名称、研究目标和少量基础事实，但并不需要共享全部材料。

财务分析器不必看到所有用户评论，产品分析器也不需要完整财报附注。

更合理的方式是：

> 每个工作单元只拿完成自己任务所需的信息，最后交换结构化结果。

## Isolation 不等于 Multi-Agent

即使系统只有一个模型，也可以在不同步骤构造不同 Context。

Multi-Agent 只是把这种边界进一步变成多个独立执行者。

所以 Isolation 更底层：

> **先学会划信息边界，再讨论要不要划 Agent 边界。**

## 安全问题也在这里出现

敏感信息如果某一步不需要，就不应该因为“前面已经读过”而自动向后传播。

这和最小权限原则很像：

- 权限只给当前动作需要的；
- Context 只给当前判断需要的。

两者一起，才构成真正可控的系统边界。

## 地图坐标

Isolation 主要作用于 **Select + Lifecycle**。

它让 Context 从“全局共享内存”变成按任务范围流动的信息。
