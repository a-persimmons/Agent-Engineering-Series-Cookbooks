# 15｜Isolation：不是所有信息都应该共享

一个复杂任务经常同时包含多个子问题。

如果所有子任务共享全部 Context，容易出现：

- 无关信息相互干扰；
- 某个子任务的假设污染另一个子任务；
- 敏感数据越过不该越过的边界；
- 窗口快速膨胀。

Isolation 的思路是：**让每个工作单元只看到它需要的部分。**

## 一个例子

研究一个公司时，可以拆成：

- 财务分析；
- 产品分析；
- 市场分析；
- 风险分析。

每个分析器需要的资料不同。

不必让财务分析器看到所有用户评论，也不必让产品分析器看到完整财报附注。

最后只把各自的结构化结论汇总。

## Isolation 不等于 Multi-Agent

即使只有一个模型，也可以对不同步骤构造不同 Context。

Multi-Agent 只是把这种边界进一步实体化。

所以更底层的能力是：

> 能不能为一个子任务建立清楚的信息边界。

## 安全也依赖 Isolation

敏感信息如果不需要进入某一步，就不要因为“反正模型已经拿到了”而继续传递。

最小必要 Context 和最小权限原则其实很接近。

## 地图坐标

Isolation 主要影响 **Select + Lifecycle**。

它也是从 Context Engineering 通往 Agent、Multi-Agent 和 Harness 的一座桥。
