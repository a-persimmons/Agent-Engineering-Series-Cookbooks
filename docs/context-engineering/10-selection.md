# 10｜Selection：Context Engineering 最核心的动作

如果第二册只能保留一个动作，我会选 Selection。

因为 Context Engineering 的很多复杂技术，最终都在回答同一个问题：

> 当前这一步，哪些信息值得进入模型注意力？

## Selection 不是检索算法的同义词

你可能从向量库选文档，也可能从对话历史选消息，从长期 Memory 选事实，从工具结果选字段。

对象不同，问题相同。

## 一个实用判断：决策价值

一段信息值不值得进入 Context，可以问：

> 如果删掉它，当前决策错误的概率会明显上升吗？

如果不会，它可能不值得占用这一轮的注意力。

这个问题比“这段资料和用户问题相关吗”更严格。

“相关”很宽；“影响当前决策”更接近工程目标。

## Selection 应该基于任务阶段

同一个信息，在不同阶段价值不同。

做市场研究时：

- 收集阶段需要广；
- 比较阶段需要统一维度；
- 决策阶段只需要最关键证据和风险。

如果每一阶段都携带全部资料，Context 会越来越重。

## 选择也包括“暂时不加载”

很多信息不是不重要，而是**现在不需要**。

例如 Agent 知道某个工具能查数据库即可，不需要提前把数据库内容放进上下文。

需要时再获取，就是 Just-in-time Context。

## 地图坐标

Selection 是整张地图的中心。

Source 决定“有什么”，Select 决定“现在用什么”。后面的 Shape、Budget 和 Lifecycle 都建立在它之上。
