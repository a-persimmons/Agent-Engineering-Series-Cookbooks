# 10｜Selection：决定“现在看什么”

前面几章一直在讨论 Context 从哪里来。

到了这里，问题第一次真正收紧：

> 手里明明有很多信息，为什么这一轮只应该给模型其中一部分？

这就是 Selection。

## “相关”还不够

一段资料和当前任务相关，并不代表它值得现在进入 Context。

比如你正在判断一次支付故障的直接原因。

过去半年所有支付事故都“相关”，但真正影响当前判断的，可能只有：

- 这次请求的 trace；
- 当前部署版本；
- 故障前后的连接池指标；
- 最近一次配置变更。

因此，比“是否相关”更有用的问题是：

> **删掉这段信息，会不会明显提高当前决策出错的概率？**

如果不会，它可能应该留在外面。

## 同一条信息，在不同阶段价值不同

研究一个市场时，早期需要尽量广地收集。

进入比较阶段后，需要的是统一维度的数据。

到了最终决策阶段，最重要的可能只剩关键证据、风险和未决问题。

Context 如果一直只增不减，就会把前一阶段的工作材料拖进下一阶段。

Selection 的价值就在这里：让工作集跟着任务阶段一起变化。

## “暂时不加载”也是选择

很多信息不是没用，而是现在没用。

Coding Agent 不需要一开始读完整个仓库；它可以先看目录，再搜索符号，再打开相关文件。

研究 Agent 也不需要预先加载所有资料；它只需要知道资料在哪里，以及什么时候去拿。

这类按需获取，后面会进入 Just-in-time Context。

## 地图坐标

Source 回答“系统拥有什么”。

Selection 回答“模型此刻应该看到什么”。

从这一章开始，Context Engineering 真正从信息收集进入信息取舍。
