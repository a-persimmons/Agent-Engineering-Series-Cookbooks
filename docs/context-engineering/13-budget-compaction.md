# 13｜Budget：Context 的真正稀缺资源是注意力

谈 Context Budget 时，人们最先想到 token 上限。

但真正影响质量的，往往更早发生：模型虽然还能装下，却已经被大量低价值内容分散注意力。

## Budget 不只是长度

可以把它理解成三种预算：

- **容量预算**：窗口能放多少；
- **注意力预算**：模型能否抓住关键内容；
- **成本预算**：每轮输入带来的延迟和费用。

三者通常同时存在。

## Trimming、Summarization、Compaction 不一样

### Trimming

直接删除低价值内容。

适合明显无用、重复或已经过期的信息。

### Summarization

把一段历史压缩成更短表示。

适合保留主要语义，但可能丢细节和证据。

### Compaction

更强调为“后续继续工作”重建一个可用状态。

它通常不只是摘要，而是保留：

- 当前目标；
- 已完成工作；
- 关键决策；
- 未解决问题；
- 必要证据；
- 下一步。

## 压缩最怕丢掉未来需要的细节

因此不要只问：

> 这一段能不能压短？

还要问：

> 后面的哪些决策可能需要回到原文？

高风险细节可以保留指针或来源，让系统需要时重新加载。

## 地图坐标

Budget 不是“接近上限才处理”。

成熟系统会持续维护高价值工作集，而不是等 Context 爆掉后才做一次大清理。
