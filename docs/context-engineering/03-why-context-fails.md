# 03｜Context 为什么会失效

模型答坏时，我们很容易说“上下文不够”或者“上下文太长”。

这两个说法太粗。

真正有用的是把 Context Failure 拆开。

## 六类常见失败

### Missing

模型缺少完成当前判断所需的信息。

例如要求判断退款是否合规，却没提供最新退款规则。

### Noise

有用信息存在，但被大量无关内容包围。

例如为了分析一个接口问题，把整个项目日志全部塞进去。

### Conflict

上下文里同时存在相互矛盾的事实或规则，却没有优先级。

### Stale

信息过去正确，现在已经过期。

长期运行 Agent 特别容易遇到这一类问题。

### Duplication

相同事实在历史、摘要、Memory、RAG 里重复出现，浪费注意力，也可能让某个观点显得“证据很多”。

### Misplacement

信息本身正确，但出现的位置、形式或时机不对。

比如一段关键约束藏在几十页工具输出之后。

## 同一种表面错误，根因可能不同

模型“用了旧价格”：

- 可能是没有新价格：Missing；
- 可能是新旧价格同时存在：Conflict；
- 可能是旧价格被写进长期 Memory 没失效：Stale；
- 也可能是新价格在 Context 末尾被噪声淹没：Misplacement / Noise。

如果只说“RAG 不准”，修复方向会很模糊。

## 从这一章开始，先给失败起名字

以后看到 Context 问题，先问：

~~~
Missing?
Noise?
Conflict?
Stale?
Duplication?
Misplacement?
~~~

这会成为第二册的调试入口。
