# 17｜重新理解 Memory：它是一套写入、选择和遗忘机制

很多 Memory 方案一上来就讨论向量库。

这容易把问题降格成“存在哪里”。

真正的问题至少有三个：

1. 什么值得写入？
2. 什么时候值得取回？
3. 什么时候应该更新、合并或删除？

## Write

不是每句话都值得记。

更值得写入的通常是：

- 稳定偏好；
- 已确认事实；
- 重要决策；
- 可复用经验；
- 后续任务明确需要的信息。

写入前最好去重，并区分“事实”和“推断”。

## Retrieve

读取策略不应该只有相似度。

还可以考虑：

- 当前任务类型；
- 时间；
- 来源；
- 置信度；
- 用户或项目范围；
- 是否已经过期。

## Forget / Update

遗忘不是缺陷，是 Memory 的必要能力。

如果旧偏好、旧状态和新事实永久共存，Memory 会逐渐变成冲突源。

所以成熟 Memory 更像：

~~~
Write
↓
Consolidate
↓
Retrieve
↓
Validate
↓
Update / Expire
~~~

## Memory 与 State 的边界

Task State 回答“这个任务现在在哪里”。

Long-term Memory 回答“过去有哪些信息值得在未来重新使用”。

不要用长期 Memory 存每一步执行状态，也不要让临时 State 永久污染用户记忆。

## 地图坐标

Memory 最完整地覆盖 **Source + Select + Lifecycle**。

它不是数据库功能，而是一套信息治理规则。
