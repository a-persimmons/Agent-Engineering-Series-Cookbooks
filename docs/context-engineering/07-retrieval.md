# 07｜Retrieval：不要把知识库当附件

RAG 最常见的错误理解是：

> 有很多资料 → 搜几段 → 塞进 Prompt。

真正的问题应该是：

> 当前这个判断缺什么信息，怎样找到最有用的证据？

Retrieval 是 Context Selection 的一种实现。

## 检索前先定义 Need

用户问“这个合同能不能提前终止”。

如果系统不知道当前决策需要：

- 终止条款；
- 违约条件；
- 适用地区；
- 合同当前状态；

那么检索只能围绕表面关键词找相似文本。

Need 越清楚，Retrieval 才越有方向。

## 相似不等于有用

Embedding 相似度高，只说明文本在某种表示空间里接近。

它不保证：

- 事实最新；
- 来源权威；
- 条款适用于当前对象；
- 能回答当前子问题。

所以成熟 RAG 通常还需要 metadata、过滤、rerank、来源优先级和结果去重。

## 检索结果也需要 Shape

不要把所有 chunk 原样拼起来。

可以为每条证据保留：

- 来源；
- 时间；
- 相关段落；
- 为什么被选中；
- 是否与其他来源冲突。

这样模型更容易区分“事实”和“文档噪声”。

## 地图坐标

RAG 主要落在 **Source + Select + Shape**。

它不是独立世界，而是“动态构造当前 Context”的一种方式。
