# 07｜Retrieval：当信息不在当前 Context 里

Retrieval 解决的不是“怎样把知识库接给模型”，而是更朴素的问题：

> 当前判断缺少的信息，能不能从外部找到？

它首先是一种 **Source**。

## 先问缺什么，再决定怎么搜

用户问：

> 这个合同能不能提前终止？

系统真正缺的可能是：

- 终止条款；
- 违约条件；
- 合同当前状态；
- 适用地区。

如果没有先识别 Need，只拿用户原话做相似度搜索，返回的文本可能“很像”，却无法支持决定。

## Retrieval 的产物应该是证据候选

检索结果不是答案。

它只是进入下一步筛选的候选信息。

因此至少要保留：

- 来源；
- 时间或版本；
- 对应原文；
- 与当前子问题的关系。

如果同一个问题命中多个来源，也不要急着全部塞进去。它们可能重复，也可能冲突。

## 相似度只是一种信号

Embedding 相似说明文本在表示空间里接近，不等于：

- 来源权威；
- 事实最新；
- 规则适用于当前对象；
- 内容足以回答当前问题。

metadata、权限、时间、来源优先级常常比“再换一个 Embedding 模型”更重要。

## 这一章先停在 Retrieval

后面第 16 章会把 Retrieval 放回完整 RAG Pipeline，讨论过滤、重排、去重、Shape 和最终评测。

这里先记住一件事：

**Retrieval 负责把可能有用的信息带到门口；是否让它进入 Runtime Context，是 Selection 的工作。**
