# 04｜Instructions：最稳定的 Context

System Instructions 往往是 Runtime Context 里最稳定的一层。

它适合放那些**长期有效、跨任务复用、具有高优先级**的规则。

例如：

- 产品的基本行为边界；
- 安全要求；
- 工具使用原则；
- 输出语言；
- 一组稳定的责任定义。

## 不要把所有知识都塞进 Instructions

一个常见演化路径是：某次出错，就往 System Prompt 加一句。

几个月以后，它变成一份混合文档：

- 永久规则；
- 临时补丁；
- 业务知识；
- 示例；
- 旧事故经验；
- 已经过期的限制。

这会制造 Conflict 和 Stale Context。

更好的问题是：

> 这条信息真的应该每一次调用都存在吗？

如果答案是否，它就不应该长期驻留在 Instructions。

## Instructions 更适合“规则”，不适合“世界状态”

例如：

“退款规则以当前政策文档为准”适合写在 Instructions。

“2026 年 10 月退款政策第 3 条是……”更适合通过 Retrieval 动态加载。

前者定义行为原则，后者是可变化事实。

## 稳定层应该尽量短

越稳定的层，越应该克制。

因为它会出现在大量调用中，任何冗余都会被反复支付成本，也会持续占用注意力。

## 地图坐标

Instructions 是一种 **Source**，生命周期通常最长。

它提醒我们：Context Source 不只是“知识库”，还包括控制模型行为的稳定规则。
