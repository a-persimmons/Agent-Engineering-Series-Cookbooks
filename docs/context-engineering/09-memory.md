# 09｜Long-term Memory：记住什么，比记得住更重要

长期记忆听起来像一个存储问题，实际上首先是一个选择问题。

如果系统把所有对话、所有事实、所有偏好都永久保存，Memory 很快会变成另一个噪声池。

## Memory 至少有三类

### 稳定事实

例如用户长期偏好、项目固定约束、组织规则。

### 事件记忆

过去发生过什么，例如某次事故、某次决策、某次失败尝试。

### 工作经验

系统从历史中提炼出的可复用规律，例如“这个仓库的部署必须先更新 base path”。

这三类信息的写入和读取策略不应该一样。

## 记忆的两个危险

### 写得太勤

每一轮都写，结果会产生大量重复、低价值和互相冲突的信息。

### 读得太勤

每一轮都把所有长期记忆取回，等于重新制造 Context Noise。

所以 Memory 的完整流程应该是：

~~~
事件发生
  ↓
判断是否值得记
  ↓
写入 / 更新
  ↓
未来任务出现
  ↓
判断是否相关
  ↓
按需取回
  ↓
进入 Runtime Context
~~~

## 记忆需要“更新”，不只是“新增”

如果用户偏好从 A 变成 B，旧记忆不能一直和新记忆并存。

有些记忆需要：

- 覆盖；
- 合并；
- 降低置信度；
- 设置过期时间；
- 标记来源。

否则 Stale 和 Conflict 会逐渐积累。

## 地图坐标

Memory 属于 **Source + Select + Lifecycle**。

“能保存”只是最容易的一步；真正困难的是决定什么时候写、什么时候读、什么时候忘。
