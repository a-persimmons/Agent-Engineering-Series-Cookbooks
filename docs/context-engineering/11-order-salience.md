# 11｜Order：正确的信息也可能放错位置

Context 不是一个无序集合。

同样的信息，以不同顺序、不同层级出现，模型感受到的重要性可能不同。

## 先把最重要的层分开

复杂 Context 至少应该区分：

- 高优先级规则；
- 当前任务；
- 当前状态；
- 当前证据；
- 历史背景；
- 示例；
- 工具结果。

如果把它们全部混成一段长文本，模型需要自己判断每句话的角色。

## 位置问题经常被误诊成“模型忘了”

例如关键限制只在很早的历史消息里出现一次，后来又堆了大量工具输出。

模型违反限制时，你可能觉得它“忘记了”。

更准确的说法是：当前 Runtime Context 对这条限制的显著性不够。

## 重复强调也有副作用

为了提高显著性，把同一规则复制三遍并不是稳妥策略。

重复会：

- 浪费预算；
- 增强某条规则的权重但破坏整体平衡；
- 增加版本不一致的风险。

更好的做法是把重要规则放到明确、稳定、高优先级的位置。

## 顺序应该服务于读取任务

一个常见结构：

~~~
稳定规则
当前 Goal
当前 State
当前输入
相关证据
工具能力
输出合同
~~~

这不是万能模板，但它体现一个原则：先让模型知道“现在要做什么”，再给它完成任务所需材料。

## 地图坐标

Order 属于 **Shape** 的一部分，也直接影响 **Budget** 的有效利用。

Context 正确不代表 Context 有效；信息必须出现在模型容易使用的位置。
