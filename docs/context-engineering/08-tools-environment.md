# 08｜Tool Result：环境会不断改写 Context

Agent 一旦开始调用工具，Context 就不再只由“预先准备的资料”组成。

每一次工具调用都会产生新的观察：

~~~text
Model → Action → Tool → Result → 下一轮 Context
~~~

这让 Context 变成动态对象。

## 工具结果为什么不能无脑保留

工具常返回大量原始数据：

- 搜索结果几十条；
- SQL 返回上千行；
- Shell 输出几万字符；
- 编译器日志持续追加。

如果全部原样留在 History，窗口会迅速被工具噪声占满。

## 工具结果需要三步处理

### 保留原始事实

必要时把原始结果存到外部存储，不要丢失。

### 提取当前步骤需要的部分

下一轮模型通常只需要少量关键信息。

### 更新 State

如果工具结果改变了任务状态，把变化写进显式 State，而不是让模型以后重新翻日志。

例如：

~~~text
原始 SQL：5000 行
        ↓
当前 Context：发现 37 条异常订单，时间集中在 14:02–14:05
        ↓
State：异常窗口 = 14:02–14:05，下一步检查支付服务
~~~

## 工具是 Just-in-time Context 的入口

有些信息不值得提前加载。

只要模型知道“需要时可以查”，就能通过工具在合适时机获取。

这比把整个数据库、整个仓库、所有 API 文档预先塞进 Context 更合理。

## 地图坐标

Tool Result 属于 **Source**，但真正的工程难点在 **Select + Shape + Lifecycle**。
