# 14｜Markdown、XML 与结构

当 Prompt 只有三句话时，格式几乎不重要。

当里面同时包含任务、资料、例子、规则、历史、输出要求时，结构才开始成为问题。

## 结构的核心作用：分隔语义区域

一个复杂 Prompt 可以被看成几个区块：

~~~
任务
背景资料
输入数据
示例
规则
输出要求
~~~

Markdown 标题、XML 标签、分隔符的价值，都在于让这些区域的边界更明确。

## 不要陷入“哪种格式最好”

Markdown 和 XML 并不存在一个适用于所有模型、所有任务的绝对胜者。

选择标准应该更实际：

- 人要经常维护：Markdown 可读性高。
- 需要清晰嵌套和边界：XML 很直观。
- 程序必须解析：让真正的结构化输出机制负责，不要只依赖文本约定。

## 一个比格式更重要的问题

结构化之前先问：

> 这些内容真的都应该出现在同一个 Prompt 里吗？

如果一个 Prompt 已经有十几个区块，真正的问题可能不是缺少 XML，而是职责没有拆开。

## 结构是地图，不是装饰

好的结构让维护者一眼看出：

- 哪部分定义 Goal。
- 哪部分提供 Context。
- 哪部分规定 Process。
- 哪部分定义 Output。
- 哪部分写 Constraints。

如果只是给每句话套标签，却仍然职责混乱，那只是“格式化的混乱”。

## 挂回地图

结构不是第七个原语。

它只是把前六个原语表达清楚的一种组织手段。
