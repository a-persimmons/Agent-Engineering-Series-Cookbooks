# 附录｜Prompt 设计与评审清单

这不是写 Prompt 时必须逐项填写的模板，而是一张排错清单。

## Goal

- [ ] 真实任务是什么，而不是主题是什么？
- [ ] 谁会使用结果？
- [ ] 结果之后要做什么动作或决策？
- [ ] 什么算完成？

## Context

- [ ] 模型完成任务必须知道哪些事实？
- [ ] 有没有把“模型应该知道”误当成“模型一定知道”？
- [ ] 是否存在无关或冲突信息？
- [ ] 是否需要示例？示例是否包含边界案例？

## Process

- [ ] 任务是否真的需要分步？
- [ ] 中间步骤有没有明确产物？
- [ ] 哪些中间结果需要检查？
- [ ] 是否把不需要的复杂推理强加给简单任务？

## Output

- [ ] 输出给人还是给程序？
- [ ] 必填内容是什么？
- [ ] 缺失值怎么表达？
- [ ] 格式与字段语义是否都清楚？
- [ ] 是否能够自动校验？

## Constraints

- [ ] 哪些事实不能猜？
- [ ] 哪些动作不能做？
- [ ] 信息不足时怎么办？
- [ ] 规则冲突时谁优先？
- [ ] 失败时怎样停止或降级？

## Evaluation

- [ ] 有没有正常案例？
- [ ] 有没有边界案例？
- [ ] 有没有真实历史失败案例？
- [ ] 指标是否对应真实业务目标？
- [ ] 修改后是否做回归？
- [ ] Prompt、模型与测试集版本是否被记录？

## 最后的判断

如果你发现一个 Prompt 已经越来越长，却仍然无法解决问题，问：

- 这是知识获取问题吗？
- 是长期状态问题吗？
- 是工具与行动问题吗？
- 是权限与可靠性问题吗？

如果答案是“是”，不要再继续堆 Prompt。该往系统层走了。
