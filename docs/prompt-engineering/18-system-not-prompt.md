# 18｜别再优化 Prompt，优化系统

Prompt 有边界。

很多团队越过这个边界后仍然做同一件事：加规则、加示例、加“务必”、加更复杂的结构。

结果是 Prompt 越来越长，系统却没有更可靠。

## 四个停止继续堆 Prompt 的信号

### 1. 缺少外部知识

需要实时数据、企业文档或数据库时，继续写 Prompt 不能创造事实。

需要 Retrieval、RAG 或 Tool。

### 2. 任务跨越多个阶段

需要搜索、验证、重试、等待外部结果时，应该考虑 Workflow 或 Agent Loop。

### 3. 需要长期状态

如果下一轮必须知道“已经做过什么”，单次 Prompt 不足以承担状态管理。

### 4. 需要强约束执行

权限、预算、超时、沙箱、重试次数，不应该只靠一句自然语言规则。

这些应该由程序和 Harness 执行。

## 一个重要转变

Prompt 层表达的是：

> “请不要做 X。”

系统层表达的是：

> “程序根本不给你做 X 的权限。”

后者更可靠。

## Prompt Engineering 的成熟标志

不是把所有问题都解决在 Prompt 里，而是知道：

- 什么适合放在 Prompt。
- 什么应该放到 Context 管理。
- 什么应该交给程序。
- 什么必须由 Eval 验证。
- 什么需要 Harness 兜底。
