# 20｜三类任务，三种设计方式

同一张地图，不等于所有任务都写成同一种 Prompt。

真正成熟的做法，是根据任务类型调整每一层的权重。

## 任务一：信息抽取

例如从合同里抽取甲方、金额、到期日。

重点通常是：

~~~
Context
+ Output
+ Constraints
+ Evaluation
~~~

Process 不需要很复杂。

真正值得花时间的是字段语义、缺失值策略、边界样本和 Schema 合法率。

## 任务二：复杂分析

例如事故根因分析、代码审查、商业判断。

重点通常是：

~~~
Goal
+ Context
+ Process
+ Evaluation
~~~

需要明确成功标准，也需要设计中间产物与证据链。

输出格式当然重要，但往往不是主要瓶颈。

## 任务三：创作

例如写文章、脚本、课程。

重点往往变成：

~~~
Goal
+ Context
+ Examples
+ Output
~~~

“好”的定义更主观，所以 Examples 与 Rubric 会更关键。

可以给两篇“这就是我要的感觉”的样本，再把真正重要的编辑标准写清楚。

## 练习：先别写 Prompt

为下面三个任务分别填写六格：

1. 帮我比较两个工作 Offer。
2. 从用户反馈中找产品机会。
3. 把一篇技术文章改写给小白看。

每个任务只写：

- Goal
- Context
- Process
- Output
- Constraints
- Evaluation

写完以后，再决定是否需要 Role、Few-shot、CoT、XML。

顺序不要反过来。

## 你真正要练成的动作

不是“看到任务就开始打字”，而是：

> **看到任务，脑子里先出现六个空格。**

当这个动作变成习惯，地图才真正长进脑子里。
