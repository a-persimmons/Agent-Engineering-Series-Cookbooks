# 21｜当上下文开始失控

到目前为止，我们一直默认一件事：需要的信息都能放进这一轮。

现实很快会打破这个假设。

## 长上下文的问题不只是“装不下”

即使上下文窗口足够大，也仍然会遇到：

- 关键信息被大量噪声稀释。
- 多份资料互相冲突。
- 历史决策与最新状态混在一起。
- 重复内容持续占用注意力。
- 每轮都发送全部内容，成本迅速上升。

所以真正的问题不是：

> 最多能放多少 token？

而是：

> **这一轮值得占用模型注意力的内容是什么？**

## Prompt 开始变成动态对象

简单应用里，Prompt 可能是一段固定文本。

复杂系统里，它更像一次动态组装：

~~~
固定规则
+ 当前任务
+ 当前状态
+ 相关历史
+ 检索资料
+ 工具定义
+ 工具结果
+ 用户最新输入
~~~

不同轮次的内容应该不同。

## 一个典型错误

为了“保证模型知道全部背景”，每轮把整个历史重新塞进去。

短期看省事，长期会出现：

- 旧信息压过新信息。
- 已完成任务继续占空间。
- 过期规则仍然存在。
- 相关性越来越差。

这已经不是“Prompt 怎么写”的问题。

## 挂回地图

Context 这个原语没有消失，反而变得更重要。

只是问题从：

> “Prompt 里应该写什么？”

升级成：

> **“系统应该怎样在运行时为这一轮构造 Context？”**

这就是下一章的主题。
