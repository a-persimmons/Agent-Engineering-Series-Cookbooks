# Prompt Engineering：从需求到可控行为

> 这不是一本提示词模板书。它想训练的是另一种能力：面对一个从未见过的任务，你知道该问什么、该控制什么、哪里可能失败，以及失败后该改哪里。

很多人学 Prompt Engineering 的路径都差不多：先看到 Role，再看到 Few-shot，然后是 CoT、XML、JSON、Self-Consistency。每一个概念都能理解，真正做任务时却仍然只能“把需求尽量说清楚”，或者让 AI 帮自己重写一遍提示词。

问题不在于学得少，而在于知识没有长在一棵树上。

这本书只保留一条主线：

**Goal → Context → Process → Output → Constraints → Evaluation**

以后遇到任何新技巧，先问它在这条链上解决什么问题。找不到位置的知识，先不要背。

## 读完以后，你应该能做到什么

你不需要背模板，但应该能独立完成四件事：

1. 把一句模糊需求改写成可执行的任务规格。
2. 判断一次失败究竟来自目标、上下文、过程、输出、约束还是评价。
3. 设计一组案例，让 Prompt 的修改可以被验证，而不是“感觉更好了”。
4. 知道什么时候继续改 Prompt 已经没有意义，应该进入 Context Engineering 或系统设计。

## 怎么读

每章都尽量遵循同一个节奏：

**先遇到问题 → 看见失败 → 找到原因 → 引入方法 → 挂回地图。**

不要急着抄示例。先问自己：这一章究竟改变了哪一个变量？

如果只能记住一页，请记住下一页的核心地图。
