# 10｜Rubric：把“好”拆成可以判断的条件

“回答质量好不好？”

这个问题对 Judge 来说太宽。

Rubric 的作用，是把 Target 拆成单项可判断标准。

例如技术根因分析：

~~~text
1. Root cause 是否正确
2. 是否提供真实证据
3. 是否区分事实与假设
4. 下一步验证动作是否可执行
5. 信息不足时是否正确表达不确定性
~~~

## 好 Rubric 的三个特点

### 具体

“专业”太抽象。

“每个结论必须绑定输入中的证据”更具体。

### 独立

尽量避免一条标准同时判断五件事。

否则失败后不知道哪里有问题。

### 有例子

给 Judge 几个 Pass / Fail 示例，会比长定义更稳定。

## Rubric 应该从 Failure 里生长

某类真实事故反复出现：

> 模型把推测写成事实。

那就增加一条明确标准：

> Unsupported Claim = Fail

Rubric 不应该只在项目开始时设计一次。

## 评分还是 Pass / Fail

能二元判断的标准，优先 Pass / Fail。

只有真正连续变化的质量维度，再考虑 1–5 分。

这样一致性通常更高。

## 地图坐标

Rubric 把 Target 变成 Judge 可以执行的判断规则。

它是 Eval 从“感觉”走向可复现的关键一步。
