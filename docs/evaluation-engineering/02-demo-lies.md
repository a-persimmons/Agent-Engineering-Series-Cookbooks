# 02｜为什么 Demo 很容易骗过我们

AI Demo 有一个天然优势：

> 人会主动挑“看起来能成功”的案例。

我们试三五个问题，结果不错，很容易得出：

> 这个方案可用了。

真实用户不会替系统挑输入。

## Demo 常漏掉什么

- 信息不足；
- 输入特别长；
- 规则冲突；
- 模糊表达；
- Tool 失败；
- 过期数据；
- 边界权限；
- 长任务中断；
- 重复副作用。

这些恰恰是生产系统最常失败的地方。

## 模型还有随机性

同一个输入，可能一次很好，下一次一般。

所以单次“成功截图”证明不了稳定性。

## Eval 的第一个价值：打破幸存者偏差

把案例固定下来，重复运行。

系统才第一次面对：

> 不是由开发者临时挑选、也不是只跑一次的输入。

## 从“展示能力”切到“寻找失败”

Demo 问：

> 它能不能做到？

Eval 更应该问：

> **它在哪些条件下做不到？**

这两个视角会产生完全不同的工程结果。

## 地图坐标

Evaluation 的 Cases 不是为了证明系统很厉害。

它们是主动寻找系统边界。
