# 06｜Dataset：测试集应该像真实世界，而不是像考试题

Eval Dataset 最容易出现的问题是“太干净”。

输入清楚，信息完整，没有冲突，格式统一。

真实用户不是这样。

## Dataset 应该覆盖任务分布

至少考虑：

- 高频正常案例；
- 低频高风险案例；
- 信息不足；
- 模糊输入；
- 边界值；
- 长输入；
- 多意图；
- 真实历史失败。

## 不要只手写理想案例

最有价值的数据往往来自生产。

因为真实失败会暴露开发者没想到的输入模式。

一个长期 Eval Set 应该不断吸收：

> 线上真实失败 → 清洗 → 标注 → 回归案例

## Dataset 要版本化

如果测试集不断变化，却只比较总分，很容易误判版本趋势。

至少记录：

~~~text
dataset_version
case_id
source
category
risk
expected
~~~

## 小而精可以先开始

刚开始不需要一千条。

20～50 条高质量、覆盖明显边界的案例，已经足以改变开发方式。

## 地图坐标

Cases 决定系统接受什么样的“现实考试”。

一个偏离真实分布的 Dataset，会让所有后续 Metric 看起来很好，却没有生产价值。
