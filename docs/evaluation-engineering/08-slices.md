# 08｜Slices：平均分会隐藏最危险的退化

假设总体成功率：

~~~text
V1 = 91%
V2 = 93%
~~~

看起来 V2 更好。

但如果拆开：

~~~text
普通问题: 95% → 97%
高风险退款: 92% → 71%
~~~

V2 可能根本不能上线。

![Cases 与 Slices：平均分不能替代风险切片](/diagrams/evaluation/cases-slices.svg)

## 什么是 Slice

按某个有业务意义的维度切分 Dataset。

例如：

- 任务类型；
- 风险等级；
- 输入长度；
- 语言；
- Tool 类型；
- 是否信息不足；
- 是否需要审批。

## Slice 应该来自风险，不只是数据属性

“中文 / 英文”可能有意义。

“Case ID 奇数 / 偶数”没有工程意义。

好的 Slice 能回答：

> 哪种现实条件下系统最容易失败？

## 高风险 Slice 可以有更严格阈值

总体 95% 不代表所有子集都要 95%。

支付、医疗、安全等高风险类别可能要求接近零容忍某些错误。

## 地图坐标

Metrics 要按有意义的 Slices 展开。

平均值适合汇总，不适合隐藏问题。
