# 16｜Routing 与 Parallel：不是所有事情都要串行 Loop

Agent 系统不一定只有一条线。

有些任务更适合路由，有些可以并行。

## Routing

先判断任务类型，再进入不同处理路径。

例如客服系统：

~~~text
用户请求
↓
Router
├─ 退款
├─ 技术支持
├─ 账户
└─ 其他
~~~

这里模型主要负责 Decision。

后续流程可以是固定 Workflow，也可以是 Agent。

## Parallel

如果多个子任务相互独立，可以同时执行。

例如调研一个产品：

- 用户评价；
- 竞品；
- 定价；
- 技术能力。

并行的价值是降低总延迟，也能减少一个 Context 同时承载太多目标。

## 并行之后要合并

真正难点往往不是分出去，而是回来以后怎样合并：

- 去重；
- 处理冲突；
- 统一证据标准；
- 决定最终结论。

所以 Aggregation 本身也需要设计。

## 不要为了“Multi-Agent”才并行

同一个模型、多个并行任务也可以实现并行。

Agent 数量不是架构复杂度的唯一指标。

## 地图坐标

Routing 改变 **Decision**。

Parallel 改变 **Loop 的拓扑结构**。

它们让 Agent 从一条线开始变成图。
