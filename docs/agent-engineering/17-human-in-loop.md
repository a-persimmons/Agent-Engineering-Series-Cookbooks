# 17｜Human-in-the-loop：把人放在真正需要判断的位置

Human-in-the-loop 不是“Agent 不够智能，所以让人兜底”。

更准确的理解是：

> 有些 Decision 的风险、责任或信息条件决定了它本来就不应该完全自动化。

## 哪些地方值得让人进入

### 高风险 Action 之前

例如：

- 付款；
- 删除数据；
- 发布生产；
- 向外部发送正式内容。

### 信息不足但代价很高时

模型可以提出候选和缺失信息，把最终选择交给人。

### 偏好性决策

例如品牌风格、招聘取舍、产品优先级。

这里没有唯一正确答案。

## 人应该看到什么

审批界面不能只给一句：

> Agent 想执行 deploy，是否允许？

更有用的是：

- 当前 Goal；
- 为什么要执行；
- 会修改什么；
- 风险；
- 是否可回滚；
- 已经验证过什么。

Human-in-the-loop 本身也是 Context Design。

## 人的反馈要进入 State

如果人拒绝某个动作，下一轮 Agent 必须知道：

- 拒绝了什么；
- 原因；
- 是否允许替代方案。

否则 Agent 可能下一轮再次请求同一件事。

## 地图坐标

Human-in-the-loop 主要位于 **Feedback + Control**。

它不是自动化的失败，而是系统边界的一部分。
