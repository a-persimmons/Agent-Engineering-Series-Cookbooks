# 05｜Goal：Agent 为什么不会自然“记得目标”

长任务里，Goal 很容易被过程淹没。

Agent 查了十次资料、改了三次代码、遇到两个错误之后，当前 Context 里最显眼的内容可能已经变成“刚刚那个报错”，而不是最初任务。

## Goal 需要持续存在

一个好 Goal 不只是初始用户消息。

它应该能回答：

- 最终结果是什么；
- 哪些条件必须满足；
- 哪些事情不属于任务；
- 什么情况下可以宣布完成。

长任务中，Goal 往往需要进入显式 State。

## Goal 与当前 Step 分开

例如：

~~~text
Goal:
修复支付接口在高并发下的超时问题，并通过压测验证

Current Step:
检查连接池指标
~~~

当前 Step 会变化，Goal 不应该跟着漂移。

## Completion Criteria 很重要

Agent 如果不知道“怎样算完成”，容易出现两种问题：

- 过早停止：找到一个可能原因就结束；
- 过度工作：已经满足需求还继续优化。

停止条件其实从 Goal 就开始设计。

## 地图坐标

Goal 在 Loop 外层持续约束所有 Decision。

它不是开场白，而是 Agent 的方向锚点。
