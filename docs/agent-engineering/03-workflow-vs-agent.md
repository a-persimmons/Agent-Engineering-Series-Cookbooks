# 03｜Workflow 还是 Agent

不是所有多步骤任务都应该做成 Agent。

如果流程可以提前确定，用固定 Workflow 往往更简单、更稳定。

## Workflow

例如发票处理：

~~~text
OCR
↓
字段抽取
↓
规则校验
↓
入库
~~~

每一步和顺序都提前写好。

模型可以参与其中，但控制流主要由程序决定。

## Agent

例如排查未知线上故障：

~~~text
先看什么？
↓
根据结果决定下一步查哪里
↓
形成假设
↓
调用工具验证
↓
必要时改计划
~~~

这里很难提前写死完整路径。

模型需要参与控制流。

## 判断标准

问一个问题：

> 下一步动作能不能在运行前基本确定？

如果能，优先 Workflow。

如果必须根据中间观察动态决定，才更像 Agent。

## Agent 不是“更高级”

动态控制带来灵活性，也带来：

- 更高成本；
- 更难测试；
- 更难复现；
- 更多边界情况；
- 更大的安全面。

所以工程成熟的表现不是“什么都 Agent 化”，而是把自主性用在真正需要的地方。

## 地图坐标

Workflow 把 **Loop** 显式写死。

Agent 把一部分 **Decision** 交给模型。

后面很多设计，都在决定“控制权到底放在哪”。
