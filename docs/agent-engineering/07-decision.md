# 07｜Decision：模型真正负责什么

Agent 里最值得交给模型的部分，是那些难以提前写死、但可以根据 Context 做出的判断。

例如：

- 下一步查哪个服务；
- 该调用哪个工具；
- 是否需要更多证据；
- 当前计划要不要调整；
- 是否已经可以结束。

## 不要把所有控制都交给模型

有些决定程序更适合做：

- 权限检查；
- 超时；
- 最大步数；
- 预算限制；
- JSON Schema 校验；
- 重试上限。

这些规则确定、可执行，没有必要让模型“自觉遵守”。

## Decision 可以有不同自由度

### 低自由度

模型只能在三个固定动作里选择。

### 中自由度

模型选择工具和参数，但流程有固定阶段。

### 高自由度

模型可以自己规划、选择工具、创建子任务。

自主性越高，灵活性越大，评测和安全难度也越大。

## 一个实用原则

> 把模糊判断交给模型，把确定约束留给程序。

这会让 Agent 更容易控制。

## 地图坐标

Decision 是 Model 在 Loop 中最核心的职责。

后面的 ReAct、Planning、Routing，都是不同的 Decision Pattern。
