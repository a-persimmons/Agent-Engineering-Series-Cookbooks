# 09｜Budget：让 Agent 知道自己能花多少

Agent Loop 天然会消耗资源：

- token；
- API 调用；
- Tool 次数；
- CPU；
- 时间；
- 钱。

如果没有 Budget，系统只能等资源耗尽才停止。

## Budget 应该是显式状态

例如：

~~~json
{
  "max_steps": 30,
  "max_tool_calls": 50,
  "max_seconds": 900,
  "max_cost": 2.0
}
~~~

每一步都更新剩余额度。

## 不同任务需要不同预算

简单问答可能只允许 3 步。

深度研究可能允许几十步。

高风险生产操作即使预算充足，也可能限制写操作次数。

## 预算不只是硬停止

系统还可以根据剩余资源调整策略：

- 预算充足时广泛探索；
- 接近上限时优先验证最可能方案；
- 低预算时停止低价值分支；
- 必要时向人请求继续授权。

## Step Limit 是最简单的安全阀

即使你还没有复杂成本系统，也至少应该有：

> max_steps

它能阻止最常见的死循环。

## 地图坐标

Budget 属于 **Limits**。

它把“请节约资源”变成可计算、可强制执行的边界。
