# 08｜Retry：重试不是“再来一次”

最简单的 Retry：

~~~text
失败 → 再试三次
~~~

很危险。

因为失败原因不同，正确动作也不同。

## 先分类

### Transient

网络抖动、限流、暂时不可用。

可以指数退避后重试。

### Invalid Input

参数不合法。

需要 Repair，不是原样重试。

### Permission

权限不足。

重试不会改变权限。

### Business Failure

库存不足、状态不允许。

应该换策略或停止。

### Unknown Side Effect

请求超时，但不知道动作是否已生效。

先查询状态，不能盲目重试。

## Retry Budget

即使是临时错误，也不能无限试。

限制：

- 最大次数；
- 最大总时间；
- 最大成本；
- 每类错误不同策略。

## 把重试历史放进 Observation

模型需要知道：

> 这个动作已经失败两次，错误完全相同。

否则它可能自己再触发一轮重复。

## 地图坐标

Retry 属于 **Recovery**。

好的 Retry 不是“更有耐心”，而是根据失败语义选择下一步。
